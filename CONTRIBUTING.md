# Contributing

## Bug Fixes

We happily accept pull requests for bug fixes from anyone. To be accepted:

- The bug must be clearly reproducible.
- The fix must be covered by tests.
- A bug is defined as the service not behaving as documented. Changing behavior to suit your needs is a feature request,
  not a bug.
- One bug fix per pull request.

## Feature Requests

Pull requests implementing new features will be declined unless they come from the core team. The only exception is if
you have reached out to the core team beforehand, described what you want to do, and received pre-approval.

We are thrilled to work with any scouts working on a programming merit badge requirement — please reach out.

## Bug Reports

We welcome bug reports filed in our issue tracker as long as they are **human-generated**. If we suspect a report was
generated by AI with no human involvement, it will be closed without further interaction.

## Code Style

- Format your code with `go fmt` (enforced by CI).
- Run `make check` locally before pushing.
- Follow standard Go idioms and project conventions.

## Security

If you discover a security vulnerability, please do not open a public issue. Contact the maintainers directly.
